# Threat model

One page, at demo scale. Tecken holds no accounts, no personal data and no
secrets in the client. It plays public, openly licensed recordings.
Following the zero-trust idea (noll-tillit), no request is trusted
because of where it comes from: every input is validated at the boundary,
every response carries the same restrictive headers, and nothing in the
browser depends on a secret.

| Area                     | Threat                                                   | Control                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------ | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Input                    | Oversized, malformed or hostile text sent to `/v1/match` | zod strict schemas: text at most 200 characters, unknown fields rejected, request bodies at most 4096 bytes. Errors are problem+json with stable codes and never contain stack traces. Tests cover each case.                                                                                                                                                                                                                  |
| Abuse                    | One client floods the API                                | In-process fixed-window rate limit: 60 requests per minute per client, keyed on the first `X-Forwarded-For` address set by the ingress. **It resets when the container restarts**, including after scale to zero, and it is per replica. Accepted: at demo scale the cost of abuse is a slower demo, not data loss.                                                                                                            |
| Media supply chain       | A swapped or tampered clip                               | The media pipeline fetches each pinned Commons file once and records the SHA-256 of the original and of every derived file. A test re-hashes every committed file and fails on any mismatch. Nothing is fetched at runtime, and the dictionary's media is never fetched at all.                                                                                                                                                |
| Dependency supply chain  | A malicious or broken package update                     | Exact version pins (`save-exact`), a committed lockfile installed with `npm ci`, and `strict-allow-scripts` with an explicit allow list for install scripts. Renovate opens update PRs only after a release is 3 days old, never merges automatically, and its PRs are remade as reviewed commits. `npm audit --audit-level=high` runs in CI, along with CodeQL and, on pull requests, dependency review.                      |
| Injection in the browser | Script or style injection                                | CSP `default-src 'self'; script-src 'self'; style-src 'self'` with no `unsafe-inline` and no `unsafe-eval` (vue-i18n messages are precompiled). `object-src 'none'`, `base-uri 'none'`, `form-action 'self'`, `frame-ancestors 'none'`. The browser suite asserts zero CSP violations on every route and state, and a positive control proves the listener fires. Chromium, Firefox and WebKit all run under this same policy. |
| Storybook                | Looser policy under `/designsystem/`                     | A path-scoped CSP that differs from the base policy in exactly three directives: hashes for Storybook's own scripts and styles, and `frame-ancestors 'self'` for its preview iframe. Still no `unsafe-*`. A unit test pins the difference.                                                                                                                                                                                     |
| Transport                | Downgrade, mixed content, framing                        | HSTS (one year, subdomains), `upgrade-insecure-requests`, `nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin`, and a `Permissions-Policy` that denies camera, microphone and geolocation. Headers are identical over http and https, as a test proves.                                                                                                                                        |
| Secrets                  | Leaked credentials                                       | The client holds none. Deployment uses GitHub OIDC federation into Azure, with no stored cloud keys. No workflow reads the npm token.                                                                                                                                                                                                                                                                                          |
| Privacy                  | Tracking the user                                        | No cookies, no analytics, no third-party requests. The browser suite asserts that the app never contacts the dictionary's host.                                                                                                                                                                                                                                                                                                |

Reporting a vulnerability: see [SECURITY.md](../../SECURITY.md).
